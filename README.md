# API организационной структуры

Высокопроизводительное REST API для управления древовидной структурой подразделений и штатом сотрудников организации.

## ✨ Ключевые возможности

* **Динамические иерархии**: Поддержка бесконечной древовидной структуры подразделений с возможностью рекурсивного получения поддеревьев заданной глубины за один запрос.
* **Интеллектуальная защита дерева**: Встроенные алгоритмы валидации на лету блокируют создание циклических зависимостей (попытки перенести родительский отдел внутрь дочернего) и самоссылок.
* **Гибкие сценарии реорганизации**: При ликвидации отдела система поддерживает как полное каскадное удаление ветки, так и безопасный автоматический перевод сотрудников в другое подразделение в рамках атомарной транзакции.
* **Высокая производительность**: Оптимизированный слой доступа к данным (компонентная предвыборка `prefetch_related`) полностью исключает проблему *N+1 запросов* при генерации структуры компании.
* **Безупречная чистота данных**: Автоматический тримминг граничных пробелов и строгая валидация длины и наполнения строк для всех ключевых сущностей.

## 📡 Документация API Эндпоинтов

Все запросы и ответы используют формат `application/json`.

### 🏢 Управление подразделениями (Departments)

#### Создание подразделения
**Запрос**: `POST /api/departments/`

  Тело запроса:
  ```json
  {
    "name": "Головной офис"
  }
  ```
  *(Передача `parent_id: null` или отсутствие поля создаст корневое подразделение).*

  Ответ:
  ```json
  {
    "id": 1,
    "name": "Головной офис",
    "parent_id": null,
    "created_at": "2026-05-18T09:01:08.777616Z"
  }
  ```

#### Изменение / Перемещение подразделения
**Запрос**: `PATCH /api/departments/{id}/`

Тело запроса:
  ```json
  {
  "name": "Новое наименование отдела",
  "parent_id": 5
  }
  ```
  Ответ:
  ```json
  {
    "id": 6,
    "name": "Новое наименование отдела",
    "parent_id": 5,
    "created_at": "2026-05-18T09:06:45.939360Z"
  }
  ```
  *(Смена `parent_id` автоматически инициирует проверку на отсутствие циклов в иерархии).*

#### Получение дерева подразделения
**Запрос**: `GET /api/departments/{id}/`
**Query-параметры**:
  * `depth` *(int, по умолчанию 1, максимум 5)* — глубина вложенности возвращаемого поддерева.
  * `include_employees` *(bool, по умолчанию true)* — включать ли списки сотрудников для каждого узла.


**Логика ответа**: Возвращает рекурсивный JSON-объект, содержащий массивы `children` (вложенные отделы) и `employees` (сотрудники, отсортированные по ФИО).
  ```json
  {
    "id": 1,
    "name": "Головной офис",
    "employees": [],
    "children": [
        {
            "id": 5,
            "name": "Отдел продаж",
            "employees": [
                {
                    "id": 2,
                    "full_name": "Петров Владимир Иванович",
                    "position": "Менеджер",
                    "created_at": "2026-05-18T09:04:25.139590Z"
                }
            ],
            "children": [
                {
                    "id": 6,
                    "name": "Новое наименование отдела",
                    "employees": [],
                    "children": []
                }
            ]
        },
        {
            "id": 2,
            "name": "Отдел разработки",
            "employees": [],
            "children": [
                {
                    "id": 3,
                    "name": "Backend направление",
                    "employees": [
                        {
                            "id": 1,
                            "full_name": "Сидоров Алексей Петрович",
                            "position": "Backend Developer",
                            "created_at": "2026-05-18T09:03:09.572506Z"
                        }
                    ],
                    "children": []
                },
                {
                    "id": 4,
                    "name": "Frontend направление",
                    "employees": [],
                    "children": []
                }
            ]
        }
    ]
  }
  ```

#### Удаление подразделения
* **Запрос**: `DELETE /api/departments/{id}/`
* **Query-параметры**:
  * `mode` *(cascade | reassign)* — режим удаления. При `cascade` удаляется отдел и весь его штат.
  * `reassign_to_department_id` *(int)* — ID целевого отдела. Обязателен, если `mode=reassign`.

### 👥 Управление персоналом (Employees)

#### Добавление сотрудника в подразделение
**Запрос**: `POST /api/departments/{id}/employees/`
  **Тело запроса**:
  ```json
  {
    "full_name": "Алексеев Петр Сергеевич",
    "position": "Lead Python Developer",
    "hired_at": "2026-05-18"
  }
  ```
  **Ответ**:
  ```json
  {
    "id": 1,
    "full_name": "Сидоров Алексей Петрович",
    "position": "Backend Developer",
    "department_id": 3,
    "hired_at": "2026-05-18",
    "created_at": "2026-05-18T09:03:09.572506Z"
  }
  ```

## 📦 Быстрый запуск в Docker

Вся инфраструктура проекта полностью контейнеризирована. Для локального запуска вам понадобятся только установленные `Docker` и `Docker Compose`.

### 1. Подготовка окружения
Создайте файл конфигурации окружения `./backend/.env` в каталоге бэкенда:
```env
DJANGO_SECRET_KEY="SECRET_KEY"
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,backend
POSTGRES_DB=org_structure
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres_secret_pass
POSTGRES_HOST=db
POSTGRES_PORT=5432
```

### 2. Запуск сервисов
Запустите сборку и развертывание контейнеров одной командой:
```bash
docker compose up -d --build
```
*Система автоматически дождется готовности базы данных, применит миграции, соберет статические файлы и поднимет Nginx-шлюз.*

После запуска API будет доступно по адресу: `http://localhost/api/`

## 🛠️ Разработка и внутренний контроль качества

### Тестирование (Pytest)
Проект покрыт автоматическими интеграционными тестами. Для выполнения тестов внутри изолированной среды запустите:
```bash
docker compose exec backend pytest
```

### Стандарты кодирования (Линтинг)
Проект строго следует стандартам PEP 8 и использует экосистему `Ruff` для статического анализа кода. Конфигурация проверок описана в `pyproject.toml`. Для локальной автоматической проверки перед коммитами настроен `pre-commit`:
```bash
pre-commit install
pre-commit run --all-files
```

### Логирование
Все важные системные события (структурные перемещения, каскадные удаления, переводы штата) логируются с ротацией файлов в директорию `backend/logs/main.log`.
```bash
docker compose logs -f backend
```
